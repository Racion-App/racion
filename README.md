# Рацион · Racion

Семь вопросов — и меню на неделю со списком покупок. Бесплатно, без регистрации, без подписки, без рефералок. Сайт — [racion.app](https://racion.app).

Ответы квиза (страна, магазин и регион, взрослые и дети по возрасту, цель — похудеть / ПП / набор, аллергии, стоп-продукты, техника, приёмы пищи, бюджет своей суммой) → детерминированный планировщик → семь дней блюд с КБЖУ и стоимостью по официальным ценам страны (Росстат для России) → список покупок с округлением до упаковки, смесью и прикормом для малышей. Результат показывается сразу и целиком, рендерится как один «чек».

## Стек

| Слой | Что |
|---|---|
| Backend | Go 1.26, stdlib `net/http`, `pgx/v5`. Миграции и сид встроены в бинарь. |
| База | PostgreSQL 17. Продукты, рецепты, магазины (индекс цен), регионы и цены Росстата, планы (jsonb), события аналитики. |
| Frontend | React 19 + TypeScript + Vite. Стили — Rubby Design System (Apple HIG на Bootstrap 5.3), SCSS. Иконки — lucide-react. |
| Инфра | Docker Compose: `db`, `backend`, `frontend` (nginx раздаёт статику и проксирует `/api`). |

## Запуск

```bash
git clone --recurse-submodules https://github.com/Racion-App/racion.git && cd racion
cp .env.example .env         # при желании впиши VITE_METRIKA_ID
docker compose up --build    # http://localhost:8090
```

Postgres наружу смотрит портом `5433` (чтобы не спорить с локальным Postgres), веб — `8090`. Оба меняются в `.env`.

### Локальная разработка без пересборки образов

```bash
docker compose up -d db

cd backend
DATABASE_URL=postgres://racion:racion@localhost:5433/racion?sslmode=disable go run ./cmd/server   # :8080

cd frontend
npm install && npm run dev    # http://localhost:5173, /api проксируется на :8080
```

Тесты планировщика: `cd backend && go test ./...` — работают на seed-JSON без базы.

## Партнёрские ссылки

Реклама только там, где она отвечает на вопрос человека: «чем готовить» и «где взять продукты». Под рецептом (лист в приложении и SSR-страница) — одна строка «Где купить: Аэрогриль · Яндекс Маркет ↗» для техники, которую реально покупают (аэрогриль, мультиварка, пароварка, гриль, блендер, миксер, мясорубка; плиту и духовку не предлагаем); в «Собрать корзину» — доставки страны. Никаких баннеров, попапов и вставок в чек или квиз. Крестик прячет строку на 30 дней (`racion.partners.hide`).

Магазины — таблица `partners` (миграция 019): страна, вид `goods`/`grocery`, название, шаблон адреса с `{q}`, флаг `affiliate`, `erid`, активность, порядок. Дефолты для 22 стран (`service/partners_default.json`: Яндекс Маркет, Ozon, Wildberries, Onliner, Kaspi, Amazon, Argos, OTTO, bol, Allegro, Alza…) заливаются при старте и не перетирают правки; партнёрские параметры и erid вписываются во вкладке «Партнёры» админки (право `partners`, только admin). Слово для поиска берётся на языке страны (`i18n.LangByCountry`: в Amazon.de идём с «Heißluftfritteuse»), с уточнением `partner.q.<ключ>` («мангал» вместо «гриль» для ru/uk/kk).

Маркировка: пока флаг `affiliate` снят, подпись «Где купить» — это навигация, не реклама. С флагом — «Реклама» и `erid` (закон о рекламе РФ: токен из ОРД для каждой партнёрской ссылки; в США — disclosure), ссылки `rel="sponsored nofollow"`. События `partner_click` / `partner_hide`. Ручки: `GET /api/partners?country=`, `GET/POST /api/admin/partners`, `DELETE /api/admin/partners/{code}`.

## Цены: Росстат

`backend/internal/rosstat/` раз в сутки скачивает с rosstat.gov.ru два файла:

- `sred_potreb_cen_MM-YYYY.xlsx` — средние потребительские цены за месяц по 373 территориям (РФ, округа, регионы, города), ~130 продуктов питания;
- `nedel_sred_cen.xlsx` — еженедельные цены по РФ в целом.

Цена продукта в плане = цена по региону за последний месяц × (недельная цена по РФ сейчас / на конец того месяца) × индекс сети. Продукт → код Росстата задан в `ingredients.json` (`rosstat.item`, `factor` — например, филе дороже тушки). 319 из 476 продуктов замаплены; остальные — ручная оценка, в списке они без зелёной точки. На чеке написано, какой регион, период и доля корзины посчитаны по Росстату.

Сайт Росстата под сертификатом Минцифры — корневой и промежуточные CA вшиты в бинарь (`russian_trusted_root_ca.pem`), только для этого хоста. Если сайт недоступен, сервер работает на прошлых ценах.

## Страны и языки

Языков пятнадцать: русский, английский, немецкий, испанский, французский, итальянский, португальский, польский, украинский, турецкий, казахский, нидерландский, чешский, китайский, японский. Каждый язык — один файл `backend/locales/<код>.json`: плоский словарь «ключ → строка» плюс `_meta` (название на самом языке и по-английски, код флага, страна по умолчанию, правило множественного числа, десятичный разделитель, месяцы, формат даты). Файлы вшиваются в бинарник (`backend/locales`, `go:embed`); сервер берёт из них строки чека и страниц (`internal/i18n`), а приложение подгружает словарь по `/api/locales/<код>` и кэширует в localStorage. Чего в файле нет — берётся из `ru.json`, в списке языков у неполного перевода показывается процент.

Добавить язык — положить рядом ещё один файл, ничего больше: сервер зарегистрирует страницы `/<код>/recipes` и `/<код>/recipe/{id}`, sitemap и `hreflang` их перечислят, приложение покажет язык в списке. Черновик перевода делает нейросеть: `cd backend && go run ./cmd/racionai locales -to es,fr` переводит недостающие ключи из `ru.json` (английский — как подсказка), уже переведённые не трогает. Бэкенды `-backend`: `local` (по умолчанию; OpenAI-совместимый прокси подписки ChatGPT от ima2 на `127.0.0.1:10531/v1`, модель gpt-5.5, без ключа, тратит квоту Plus), `codex` (Codex CLI, `CODEX_BIN`; дорого по квоте — у каждого вызова системный промпт агента), `openai` (API-ключ `OPENAI_API_KEY`, gpt-5-nano, дёшево и без квоты), а также бесплатные уровни `mistral` (La Plateforme Experiment: ~1 млрд токенов в месяц, 1 запрос/с — хватает на всю базу, запускать с `-workers 1`), `gemini` (flash-lite, 1000 запросов в день), `groq`, `openrouter` (`:free`, 50 запросов в день без кредитов) и `custom` (`AI_BASE_URL`, `AI_API_KEY`, `-model`). Ключи — в `.env`, см. `.env.example`. Массовые прогоны (переводы 458 рецептов на 14 языков, названия 476 продуктов — `racionai ingredients -to …`) разумнее гнать через `openai`, штучные правки — через `local`. Так сделаны все языки кроме ru/en/de — правки в файлах приветствуются.

Язык выбирается так: явный выбор человека (localStorage `racion.lang` и cookie `racion_lang`) → языки браузера → страна по IP (`/api/lang` отдаёт `geo`; на сервере `geoLang` сопоставляет страну языку) → русский. Кнопка-переводчик в шапке (иконка с флагом текущего языка) открывает список с флагами (`flag-icons`), названием на самом языке и по-английски; на SSR-страницах тот же список — `<dialog>` в `layout.html`, логика в `public/ssr.js`. Уже собранный план при смене языка перечитывается с сервера: числа те же, подписи новые (`Localize` пересобирает названия, дни, группы списка, «почему выбрано» из `whyCode`).

Переводы рецептов лежат отдельно: `internal/seed/data/recipes_i18n_<код>.json` (id → title, description, steps); en и de сделаны вручную, остальные — `go run ./cmd/racionai recipes -to es,fr` (возобновляемый: переведённые id пропускает, файл дописывает по ходу). Seed кладёт их в `recipes.i18n` (jsonb, слияние); без перевода на язык берётся английский, потом русский (то же для названий продуктов и подборок). Запись с названием без шагов (ручная заглушка) `racionai` переводит заново. Названия продуктов (сейчас en и de; остальные языки — `racionai ingredients -to …`) и ручные цены по странам — в `ingredients_i18n.json` (цена типовой упаковки в BYN, KZT, EUR, USD по полкам Евроопта, Magnum, Rewe/Aldi и Walmart; для Европы цена Германии — ориентир, который индексируется по стране).

Помощник для своих рецептов: если на сервере есть `OPENAI_API_KEY`, в форме своего рецепта появляются «Улучшить текст» и «Перевести на …» (`POST /api/me/recipes/ai`, 20 запросов в час на человека). Нейросеть правит только название, подводку и шаги; продукты и количества считаются по базе и не меняются. Результат попадает в форму, сохраняет человек, «Вернуть как было» отменяет.

Страна выбирается на первом шаге квиза и задаёт валюту, магазины, пресеты бюджета и источник цен. Первой подставляется страна по IP посетителя: бэкенд держит в памяти базу [DB-IP Country Lite](https://db-ip.com) (CC BY 4.0, ~8 МБ, выходит раз в месяц; скачивается в фоне и хранится в таблице `geo_db`, пакет `internal/geo`), адрес берётся из `X-Forwarded-For` / `X-Real-IP`, за Cloudflare — из `CF-IPCountry`. `/api/meta` отдаёт `geoCountry`, квиз подставляет его, пока человек не выбрал страну сам (флаг `racion.country.chosen` в localStorage); SSR-страницы рецептов берут страну из cookie `racion_country`, иначе по IP, иначе по языку. Стран 22: Россия, Беларусь, Казахстан, США, Британия и 17 стран Европы (Германия, Австрия, Франция, Италия, Испания, Португалия, Нидерланды, Бельгия, Финляндия, Литва, Латвия, Эстония, Польша, Чехия, Швеция, Норвегия, Швейцария).

| Страна | Источник цен |
|---|---|
| Россия | Росстат по региону (см. ниже) |
| Беларусь | Белстат: месячный xls «Средние цены на товары» по РБ, 108 продуктов |
| Казахстан | Бюро нацстатистики: еженедельный xlsx по социально значимым продуктам, 40 продуктов |
| США | BLS Average Price Data, 33 продукта |
| Британия | ONS: средние цены по товарам (последние — январь 2025) × CPI по группам еды за текущий месяц |
| Европа | Eurostat: ориентир Германии (`ingredients_i18n.json`, декабрь 2025) × индекс уровня цен страны по категории еды (PLI, годовой) × HICP группы товара (месячный, ECOICOP v2: яйца, сыр, птица, овощи…) × курс к евро |

Адаптеры источников — в `internal/localprices`: каждый скачивает файл или API, приводит единицы (фунты, галлоны, десятки, пенсы) и сопоставляет товары с продуктами базы (`coicopOf` — группа HICP и категория PLI для каждого продукта). Результат хранится в `local_prices` и обновляется раз в сутки в фоне, как Росстат. Для продуктов, которых в источнике нет, берётся ручной ориентир, для детского питания — рублёвая цена × курс-множитель страны. На чеке видно источник, период и долю корзины по нему. Живой прогон: `LOCALPRICES_LIVE=1 LOCALPRICES_ONLY=PL,GB go test ./internal/localprices -run TestLive -v`.

Логотипы сетей — свободные SVG с Wikimedia Commons (`frontend/public/logos/README.md`, таблица с файлами и лицензиями); одна марка в разных странах использует один файл. Для сетей без свободного SVG (Беларусь, Казахстан, Carrefour, Biedronka, Conad, Rimi, Selver, Kiwi, Meny…) — монограмма в фирменном цвете (`StoreMark.tsx`).

## Премиум и фото

Тег `premium` — 23 дорогих блюда: устрицы, рибай, свиные и говяжьи рёбра, утиная грудка, гребешки, королевские креветки, мидии, каре ягнёнка, телятина, тартар, буррата, икра. Пресет бюджета «Премиум» (примерно ×3 к среднему) включает режим, в котором такие блюда получают бонус, а заметная экономия относительно цели — штраф; при обычном бюджете они идут реже. Сырое (тартар, устрицы) и морепродукты не попадают в общие блюда, если за столом ребёнок до 7 или до 3 лет.

Фото рецептов генерирует `scripts/gen_images_ima2.py` через локальную студию ima2 (GPT Image по подписке ChatGPT, `ima2 gen -q low -s 1536x1024`, одна картинка на рецепт, стоп при недельной квоте ≥ `--stop-at`); старый `scripts/gen_images.py` (Hugging Face SD3, `HF_TOKEN`) остаётся запасным. Промпт собирается из английского названия, списка продуктов и формы подачи; для спорных названий есть точечные подсказки. Файлы кладутся в `frontend/public/images/recipes/<id>.webp` (768×512), список готовых — `images.json`, по нему сидинг проставляет `image`. Папка примонтирована в nginx, пересборка не нужна.

## Семья и пожелания

Второй шаг квиза — список участников, а не счётчик взрослых: у каждого имя, аппетит (небольшой / обычный / большой) и приёмы пищи дома (кто обедает на работе — обед не считается). Третий шаг — цель каждого: похудеть, ПП, набор, без цели. Меню одно на всех (продукты, которых кто-то не ест, исключаются целиком), а порции разные: коэффициент человека = его дневной ориентир ккал / средний по семье (`planner/members.go`). Список покупок и цена считаются по сумме коэффициентов тех, кто ест этот приём (`Plan.slotPortions`), на чеке у каждого дня — ккал каждого человека (`Day.perMember`), в шапке — строка участников. Цель меню: все худеют → «похудение», кто-то худеет или следит → «правильное питание», все набирают → «набор». Старый формат `adults` + `goal` продолжает работать: сервер разворачивает его в одинаковых участников.

«Хочется на этой неделе» (`params.wants`, до 10 продуктов): блюдо с таким продуктом получает бонус в подборе, пока продукт не подан дважды, а перерасход по бюджету прощается наполовину. На чеке такое блюдо подписано «по вашему желанию: лосось».

**Раздел «Семья» в кабинете** (`households`, `household_users`): состав хранится в аккаунте — взрослые (имя, цель, аппетит, приёмы дома) и дети (имя, возраст, кормление, смесь), правит любой аккаунт семьи. Квиз у вошедшего заполняется сам: прошлые ответы из аккаунта (магазин, бюджет, техника, стоп-продукты) плюс состав из «Семьи»; поправить можно прямо в квизе на одну неделю. Владелец приглашает другие аккаунты ссылкой `/me?family=TOKEN`; все недели любого аккаунта семьи общие (видны в кабинете, можно отмечать и менять блюда), напоминания приходят по семейным неделям тоже. Аккаунт состоит в одной семье; владелец с другими аккаунтами перейти в чужую семью не может.

**Общая неделя.** Кнопка с людьми на чеке даёт ссылку `?join=1`: вошедший по ней попадает в семью плана (`plan_members`): неделя появляется у него в кабинете с меткой «общая», он видит тот же список, отмечает покупки и может менять блюда. Отмечать и добавлять товары по обычной ссылке по-прежнему может любой, менять блюда — только владелец и семья.

## Что есть дома, ответы после ужина, правки недели

**«Что уже есть дома»** (`params.have`, до 40 продуктов, тот же шаг квиза, что и «хочется»): планировщик ставит блюда с такими продуктами раньше, пока домашний запас не расписан (скоропортящиеся — с большим бонусом), а список покупок вычитает по одной типовой упаковке каждого. Позиция, которой хватает на всю неделю, остаётся в списке серой с пометкой «есть дома» и не считается в сумме; частично — «дома 500 г», покупается остаток. В итогах отдельная строка «Уже есть дома: −N».

**«Как было?»** — обратная связь после ужина без анкет. В 20:00 по времени устройства приходит push «Как борщ?» с двумя кнопками прямо в уведомлении (`actions` в `sw.js`, ответ уходит на `POST /api/recipes/{id}/feedback`); то же на чеке: у блюд прошедших дней (и сегодняшнего ужина после 19:00) вместо «заменить» стоят «понравилось / не зашло». Ответы лежат в `recipe_feedback`: «понравилось» — бонус в подборе, одно «не зашло» — штраф, два — блюдо больше не предлагается (`Social.Taste`, `params.liked` / `params.meh`). Выключается в настройках уведомлений («спрашивать вечером»).

**Правки недели без пересборки** (`planner/edit.go`): день «не дома» (кнопка-календарь в заголовке дня — блюда остаются, но не считаются в покупках и итогах, `Day.skipped`), перестановка блюд между днями (иконка «переставить» у блюда → у того же приёма в других днях появляется «Сюда»; суп на два дня не двигается), «повторить неделю» (кнопка в панели чека: та же неделя на следующие даты новым планом, отметки и пропуски сбрасываются). Ручки: `POST /api/plans/{id}/skip`, `/move`, `/repeat`.

**Режим готовки** — кнопка «Готовить» в листе рецепта: рецепт на весь экран, один шаг за раз, крупный текст, свайп и стрелки, продукты уже пересчитаны на порции, экран не гаснет (Wake Lock). Таймеры вынимаются из текста шага регулярным выражением на любом языке базы («варить 20 минут», «15–20 мин», «1 час», «10 分钟» → кнопка), идут параллельно, по окончании — звук и вибрация; полоса запущенных таймеров видна на любом шаге (`components/CookMode.tsx`).

**«Собрать корзину»** в режиме магазина: лист с ещё не купленными позициями и ссылками «Найти» на поиск интернет-магазина сети или сервиса доставки страны (`lib/cart.ts`: 5ka, Перекрёсток, Лента, ВкусВилл, Metro, Купер, Лавка, Самокат, Walmart, Tesco, Rewe, Carrefour, Mercadona, AH…) плюс «скопировать список» для приложений без поиска по ссылке. Без партнёрского API это deep-link; с партнёркой — место для дохода при бесплатном продукте.

**Динамика бюджета** — вкладка «Покупки» в кабинете: столбики по неделям «план / куплено» (`GET /api/me/budget`: план — стоимость недель пользователя, факт — отмеченные покупки) и подпись «в этом месяце вы тратите на N % меньше/больше, чем в прошлом» (по среднему дневному расходу, чтобы незаконченный месяц сравнивался честно).

**Первый визит** — лист «Добро пожаловать в Рацион» с четырьмя пунктами и кнопкой «Начать» (`components/Welcome.tsx`, один раз, флаг `racion.welcomed` в localStorage; события `welcome_start` / `welcome_skip`).

## События, коллекции, замены, картинки продуктов, PWA

**События** (`planner/occasion.go`, `seed/data/occasions.json`): не неделя, а один стол — Новый год, день рождения и гости, детский день рождения, пикник, Масленица, Пасха. У каждого курса (салаты, закуски, горячее, гарнир, десерт; у Масленицы — блины, солёное и сладкое к ним, первое; у Пасхи — кулич и пасха) есть `pool` — список рецептов, из которых собирается стол, и `must` — то, без чего стола не бывает (оливье и шуба на Новый год, шашлик и картошка по-деревенски для гостей, пицца и наггетсы детям, блины и сметана на Масленицу, кулич и крашеные яйца на Пасху). Число блюд — `base + гости/per`. Правила по тегам (`any/all/none`) остались только запасным вариантом для салатов и закусок. Праздничные рецепты лежат в `recipes_festive.json` (мясо по-французски, шашлык, буженина, медовик, кулич, начинки к блинам…) и помечены тегами `festive`/`filling` — в обычную неделю планировщик их не берёт. Событие может добавить технику к анкете (`equipment: ["grill"]` у пикника и гостей). Дорогих блюд (`premium`) — не больше одного на курс. Аллергии и стоп-продукты из анкеты действуют и на стол — страница события показывает их оранжевой плашкой с кнопкой «Снять ограничения», на чеке предупреждение о пустых курсах содержит кнопку «Убрать ограничения и собрать заново» (снимает их в черновике и пересобирает стол или неделю), в квизе на шагах аллергий и стоп-продуктов есть «Убрать все ограничения (N)». Черновик со старым пресетом «Пост» вычищается при чтении (`lib/draft.ts`). Без анкеты техника по умолчанию — плита, духовка, микроволновка. Пресет «Пост» (`/?s=1&event=lent`) действует только на ту неделю и в сохранённые ответы не пишется. Замена блюда на столе берётся из `pool` того же курса (запасные правила по тегам — только если pool пуст). Итоги стола подписаны «за стол / на гостя», а не «за неделю». Праздники по странам: у события может быть `countries` (День благодарения — US/CA, 8 Марта — RU/BY/KZ…, Октоберфест — DE/AT/CH); чипы в квизе показывают только события страны из анкеты, прямая ссылка `/event/{id}` работает всегда. Всего 13 событий: Новый год, Рождество, Хеллоуин, День благодарения, 14 февраля, 8 Марта, Масленица, Пасха, Октоберфест, день рождения/гости, детский день рождения, пикник, Пост. Рецепты праздников — `recipes_holidays.json` (тыквенный пирог, печенье-привидения и «пальцы ведьмы», сосиски-мумии, клюквенный соус, стаффинг, кукурузный хлеб, глинтвейн, имбирное печенье, стейк с перечным соусом, фондан, немецкий картофельный салат…). Страница `/event/{id}` и чипы событий в квизе.

**Коллекции** — папки рецептов в кабинете (таблицы `collections` / `collection_items`, до 30 штук, кнопка «В коллекцию» в листе рецепта и на странице). «Собрать неделю из коллекции» ведёт в квиз с `?collection=id`: рецепты коллекции получают в подборе бонус сильнее избранного (`Params.CollectionIDs`). Свою коллекцию можно открыть по ссылке (иконка «ссылка» в кабинете: `PUT /api/me/collections/{id}/public`, адрес `/collection/{slug}`, slug из названия и шести знаков id). **Редакционные подборки** («Стол на Новый год», «Быстрые ужины за 20 минут», «ПП-завтраки», «Супы на всю неделю») делает админ во вкладке «Подборки»: название, slug, описание, обложка (без обложки берётся фото первого рецепта — `coverAuto`), публичность, рецепты через поиск по базе. Название и описание переводятся в форме (блок «Переводы», JSONB `name_i18n`/`description_i18n`, `Collection.Localized(lang)`); без перевода показывается русское. Первые восемь показаны лентой в начале каталога со ссылкой «Все подборки» на `/collections` (и `/{lang}/collections`), у каждой своя SSR-страница `/collection/{slug}` (и `/{lang}/collection/{slug}`, hreflang, sitemap) с кнопкой «Собрать неделю» — работает и для гостя. Редакционные подборки не попадают в личный список владельца.

**Замены продуктов** (`seed/data/substitutes.json`, 460 продуктов, выверены вручную — нейросетевой вариант был расплывчатым и местами неверным; заметки по-русски и по-английски, `note`/`note_en`, коэффициент — сколько заменителя на единицу продукта в его единицах; в рантайме нейросеть не нужна): в листе рецепта и на странице у продукта с заменами есть иконка — всплывашка «чем заменить» с пересчётом ккал и цены порции (`service/subs.go`). Строки: продукт → 1–3 замены с коэффициентом количества и пометкой («более сухая, добавить масла»).

**Картинки продуктов** (`ingredients.image`, манифест `seed/data/ingredient_images.json`, файлы в `frontend/public/images/ingredients/`): после названия продукта в списке покупок и в рецепте стоит иконка-картинка (`components/IngredientPic.tsx`, на SSR — `.pic__btn` в `ssr.js`); по наведению, фокусу или нажатию показывается фото 160×160, вверх, у верха экрана — вниз, у правого края — влево. Генерация — `scripts/gen_ingredient_images.py` через ima2 (`--stop-at 97` останавливает по недельной квоте; скрипт возобновляемый, пропускает готовые).

**PWA**: `frontend/public/manifest.webmanifest` (иконки, `display: standalone`, ярлыки «Собрать неделю» и «Рецепты») и `sw.js`: оболочка приложения и последние планы кэшируются, `/assets/*` — сначала сеть, потом кэш (после деплоя стили не залипают), версия кэша в `VERSION`. Без сети чек открывается из кэша, отметки «куплено» копятся в очереди (`lib/offline.ts`) и уходят на сервер при появлении связи; сверху жёлтая полоска «нет сети».

**Футер** (`.sitefoot`): бренд и одна строка о продукте, колонки «Рецепты / Аккаунт / О проекте», справа язык (та же кнопка, что в шапке) — на SSR-страницах и в приложении одинаковый.

**Нейросети на сервере: пул провайдеров** (`internal/ai/pool.go`). Сервер собирает пул из всех заданных ключей — `MISTRAL_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `LOCAL_AI_URL` — в порядке `AI_ORDER` (по умолчанию mistral, gemini, groq, openrouter, openai, local; модели — `AI_MODELS=mistral=…,gemini=…`). У каждого провайдера своя пауза между запросами, лимиты в минуту и в день бесплатного уровня и «отдых» после 429 или кончившихся кредитов; запрос уходит первому свободному, при отказе — следующему. Один пул обслуживает автопроверку рецептов, помощника и очередь переводов. Состояние провайдеров — в админке на «Обзоре» (`GET /api/admin/ai`).

**Переводы своих рецептов** — автоматически: при добавлении или правке текста рецепт ставится в очередь на все языки, кроме языка оригинала (`user_recipes.lang` = язык интерфейса автора; таблица `recipe_translations`, воркер `service/translations.go`, результат в `user_recipes.i18n`). В кабинете у рецепта строка «Переводы: 5 из 14 · сейчас Español · mistral/ministral-14b-latest», по клику — чипы по языкам (готово / переводится / ошибка), какие провайдеры сейчас свободны и кнопка «Повторить недостающие» (`GET/POST /api/me/recipes/{id}/translations`). Рецепты, добавленные раньше, получают ссылку «Перевести на другие языки». Воркер переводит по одному, при 429 ждёт и продолжает; после перезапуска зависшие задачи возвращаются в очередь.

**Помощник по неделе** (`service/planchat.go`, `POST /api/plans/{id}/chat`, кнопка-искра в панели чека для вошедших): человек пишет «не нравится вторник» или «в субботу нас не будет», нейросеть видит план (дни, блюда, ккал, цена, цель, бюджет), отвечает словами и возвращает действия — `swap`, `skip`/`unskip`, `move`, — которые сервер применяет теми же сервисами, что и кнопки на чеке (права те же). Ответ показывает, что именно изменилось и какая модель отвечала. Квота — 20 запросов в час на пользователя.

**«Меньше разных продуктов»** (`Params.Compact`, тумблер на шаге бюджета): планировщик штрафует каждый новый продукт в списке и поощряет уже лежащие в корзине (специи и масло не считаются), в «почему» появляется «из тех же продуктов». На типичной неделе список короче на 20–30 % (66 → 48 позиций в тесте).

**Быстрый старт** (`.quickstart` на первом шаге квиза для вошедшего с неделями): «Открыть последнюю неделю» и «Собрать как в прошлый раз» — те же ответы, тот же магазин, новая неделя одним нажатием.

**Каталог** (`/recipes`): фильтр «Техника» кроме «только плита / без духовки / без готовки» умеет «духовка, аэрогриль (плюс рецепты для духовки), мультиварка, пароварка, микроволновка, гриль»; под них добавлен `recipes_appliances.json` (18 рецептов). Подборки — отдельная полоса с компактными карточками «фото слева» и кнопкой «Все подборки», над сеткой сегмент-вкладки «Все · Завтраки · Обеды · Ужины · Перекусы» и заголовок раздела с числом; фильтры — липкая колонка слева на широком экране, на телефоне кнопка «Фильтры» открывает панель во весь экран с кнопкой «Показать N». Всё без перезагрузки.

**Свои рецепты: публикация и статистика.** В кабинете у непубличного рецепта явная кнопка «Опубликовать» (отправляет на автопроверку, дальше по статусам), у опубликованного — просмотры страницы (`user_recipes.views`, считаются на SSR-странице не автором), лайки, «в избранном», комментарии. Помощник переводит рецепт на любой из 15 языков (выбор языка рядом с кнопкой), а не только на язык интерфейса.

## Превью ссылок и бренд

Все SSR-страницы (каталог, рецепт, подборки) отдают полный набор `og:*` и `twitter:card=summary_large_image`: заголовок, описание, `og:locale` по языку, картинка — JPEG-копия фото блюда (`images/recipes/{id}.jpg`, мессенджеры не все понимают WebP) или брендовая 1200×630 на языке страницы (`frontend/public/og/<lang>.png`, 15 штук). Страницы приложения (`/`, `/plan/{id}`, `/event/{id}`) для людей — React, а ботам мессенджеров (Telegram, VK, WhatsApp, Facebook, X, Discord, Slack, Viber, iMessage — по `User-Agent`, `map $is_bot` в nginx) nginx отдаёт ответ бэкенда `/og/…`: минимальный HTML с og-разметкой на языке cookie/Accept-Language (для недели — «Неделя с 21 сентября 2026 · 28 блюд · продукты ≈ 6 280 ₽ · Пятёрочка») и мета-редиректом на ту же ссылку.

Фирменные файлы — в `brand/` (`node brand/build.mjs`): знак-чек, монохромный знак, логотипы ru/en, аватары, обложки YouTube/VK/GitHub, посты и сторис Instagram на ru/en; тот же скрипт обновляет favicon, иконки PWA и og-картинки всех языков. Подробности — `brand/README.md`.

## Ник, лайки, избранное, комментарии

Ник (`users.nick`, уникальный без учёта регистра, `[a-z0-9_]{3,24}`) задаётся в кабинете и подписывает комментарии и свои рецепты, которыми делятся. Лайк и избранное — на странице рецепта (SSR, кнопки в `.social`, логика в `frontend/public/ssr.js`) и в листе рецепта на чеке (`SocialBar`); гость по клику уходит на вход и возвращается (`/login?next=`). Избранное — вкладка кабинета и бонус в подборе (`params.favorites` подставляет сервер, на чеке «из избранного»). Комментарии (1–500 знаков, не больше 30 в час, только с ником) рендерятся сервером и добавляются без перезагрузки; удалить можно только свой. Свой рецепт можно открыть по ссылке (кнопка «поделиться» в кабинете ставит `public` и копирует адрес) — на странице появляется «рецепт @ник». Страницы рецептов и каталога отдаются с `Cache-Control: private, no-cache` и `Vary: Cookie`: они зависят от сессии.

## Фото

Фото своих рецептов, к комментариям и аватар. Файл (JPEG/PNG/GIF/WebP до 12 МБ) уходит на `POST /api/uploads?kind=recipe|comment|avatar`, сервер пережимает его в WebP двух размеров (длинная сторона 1400 и 480, качество 82; `internal/media`, чистый Go без cgo) и кладёт в S3-совместимое хранилище — в докере это MinIO (`quay.io/minio/minio`, том `miniodata`), в продакшене подойдёт любой S3 (Selectel, Yandex Object Storage, AWS): переменные `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `S3_SECURE=1`, `S3_PUBLIC_URL`. Бакет создаётся при старте с политикой «чтение всем»; ссылки публикуются относительно `S3_PUBLIC_URL` — по умолчанию `/media`, который nginx проксирует в MinIO, так что фото те же по происхождению, что и сайт (CSP `img-src 'self'`). Оригинал не хранится. Квота — 40 загрузок в час на человека; при сохранении сервер принимает только ссылки из своего хранилища (`Media.Owns`). Без `S3_ENDPOINT` кнопки фото не показываются, всё остальное работает.

## Уведомления

Web Push без сторонних сервисов: ключи VAPID создаются при первом старте и хранятся в `settings`, подписки устройств — в `push_subscriptions`, настройки — в `users.notify`. Карточка «Уведомления» в кабинете включает их на этом устройстве (service worker `frontend/public/sw.js`) и задаёт: день и час напоминания «пора в магазин» (уходит, если в ближайшей неделе есть неотмеченные позиции), вечернюю сводку в 19:00 «завтра готовим …», воскресное «собрать новую неделю», если плана на понедельник нет. Часовой пояс берётся с устройства. Проход по подписчикам раз в 10 минут (`service/notify.go`, тест `notify_test.go`), отправленное помнится в `notifications_sent`, мёртвые подписки (404/410) удаляются. Для продакшена задайте `PUSH_CONTACT=mailto:…` и `BASE_URL` (ссылки в уведомлениях); push работает только по https (и на localhost).

| Готовим отдельно | от 6 мес | Своё детское меню на 7 дней × 4 приёма из базы `recipes_kids.json` (40 рецептов с тегом `kidmenu` и возрастом `ageN`: каши, паровые тефтели, супы-пюре, запеканки). | С общего стола | от 6 мес | Доля взрослой порции: 6–12 мес — 0,15; 1–3 года — 0,4; 3–7 — 0,55; 7–11 — 0,7; 11–14 — 0,85; старше — 1. До 3 лет из общих блюд жёстко убираются острое, грибы, колбасные изделия, морепродукты, майонез, орехи и семечки; до 7 лет — острое. До года — докорм пюре. |

Смесь можно включить в любом режиме до 3 лет. Всё детское — группой «Детское питание» в списке.

## Аккаунт

Почта и пароль, bcrypt, сессия в cookie на 90 дней. Без подтверждения почты. Что даёт:

- **Недели** — собранные планы привязываются к аккаунту, список в кабинете, удаление.
- **Не предлагать** — кнопка у блюда на чеке; рецепт уходит в `user_dislikes` и планировщик его больше не ставит (и в детское меню тоже). Возвращается из кабинета.
- **Покупки** — каждая отметка «куплено» в списке владельца плана пишется в `purchases`; кабинет показывает историю по дням за 90 дней.
- **Свои ответы** — последние параметры квиза сохраняются в `users.defaults` и подставляются в следующий раз.
- **Мои рецепты** — вкладка в кабинете: название, подводка, приём пищи, время, техника, теги, продукты из общей базы с граммовкой на порцию, шаги. Хранятся в `user_recipes` (id `u_<hex>`), в общий каталог, поиск и sitemap не попадают. При сборке и замене блюд сервер подмешивает рецепты владельца в каталог (`Catalog.WithRecipes`), они получают бонус в подборе, так что свежедобавленное блюдо обычно появляется в ближайшей неделе; калории и цена считаются по продуктам как у базовых. На чеке помечены «своё», кнопки «не предлагать» у них нет. Ссылка на план общая, поэтому такое блюдо открывается и у того, кому план переслали; HTML-страница отдаётся с `noindex`.

Без аккаунта всё тоже работает: отметки и свои товары хранятся по ссылке на план (`plan_checks`, `plan_extras`), так что список можно открыть на другом телефоне.

## Список покупок

- Отметки «куплено» синхронизируются с сервером по id плана; локальная копия в localStorage.
- **Свои товары** — «Добавить свой товар»: название, количество, дата «купить к». Группа «Своё» в конце списка.
- Дата начала недели выбирается на последнем шаге квиза (ближайшие четыре понедельника).

## Страницы рецептов

`/recipes` и `/recipe/{id}` отдаёт бэкенд обычным HTML из Go-шаблонов — для поисковиков и для ссылок. `/sitemap.xml` и `/robots.txt` там же. Стили те же: Vite собирает CSS в стабильный `/assets/app.css`, и шаблоны его подключают. Nginx проксирует эти пути на бэкенд.

**Каталог.** Страна цен, фильтры, страницы и поиск меняются без перезагрузки: `ssr.js` запрашивает тот же HTML и подменяет `<main>`, адрес меняется через `pushState`, «назад» работает, фильтры остаются раскрытыми. `?country=` в адресе важнее cookie (иначе выбор страны срабатывал со второго раза). Поиск понимает опечатки в одну букву, префиксы («греч» найдёт гречку), синонимы («курица» = «грудка», «филе») и несколько слов через И. Фильтры в раскрывающемся блоке: приём пищи, теги, основа (курица, мясо, рыба, овощи, творог), время, калории, цена, техника. Каждый фильтр — ссылка, поэтому комбинации индексируются; активные попадают в sitemap.

**Страница рецепта.** У каждого из 458 рецептов есть подводка в поле `description` — короткий текст без воды, из него же собирается meta description и JSON-LD. Дальше факты: время, ккал, цена порции, белок; продукты с ценой упаковки или килограмма по Росстату и переключателем порций (пересчёт на месте); шаги, где первое упоминание продукта — ссылка на его строку с номером; пищевая ценность с долей от 2000 ккал; техника; похожие. Блок «Коротко» появляется только когда есть что добавить: блюдо на два дня, детский возраст, пометка ПП.

Фото рецептов лежат в `frontend/public/images/recipes/` (WebP 768×512) и подключаются манифестом `seed/data/images.json` (id → путь); сгенерированы через ima2 (`scripts/gen_images_ima2.py`, возобновляемый, `--stop-at` по недельной квоте). Картинки продуктов — так же, `ingredient_images.json` и `scripts/gen_ingredient_images.py`.

## Как устроен планировщик

`backend/internal/planner/planner.go`

1. **Фильтры (жёсткие):** аллергены по ингредиентам, исключённые продукты и теги (`spicy`, `offal`), техника (рецепт требует подмножество того, что есть на кухне), выбранные приёмы пищи.
2. **Скоринг каждой ячейки (день × приём):**
   - бюджет: своя сумма на человека в день или на всех за неделю, делится по приёмам (завтрак 25 %, обед 35 %, ужин 30 %, перекус 10 %); превышение штрафуется степенно;
   - цель: калорийность блюда против нормы (похудение 1500 / ПП 1900 / набор 2600 ккал или своя); при похудении штраф за «тяжёлые» и сладкие блюда, бонус за `pp`; при наборе — бонус за `protein`/`hearty`;
   - разнообразие: штраф за тот же главный ингредиент сегодня, вчера и позавчера, повтор рецепта на неделе — почти запрет;
   - доедание: бонус, если нужный продукт уже в корзине и его остаток от упаковки покрывает блюдо (скоропортящиеся — больший бонус); штраф за новую скоропортящуюся упаковку ради малой доли;
   - время: длинные ужины в будни и долгие завтраки штрафуются;
   - детерминированный шум от seed (hash ответов) — одинаковые ответы дают одинаковую неделю.
3. **Батч-обеды:** по понедельникам, средам и пятницам обед с флагом `batch` готовится на два дня — следующий день помечен «доедаем вчерашнее», продукты считаются дважды, время у плиты — один раз.
4. **Список покупок:** суммы ингредиентов × порции (взрослый 1, дети по возрастной доле), весовое округляется до 100 г, остальное — до упаковки; цена = Росстат по региону (или запасная) × индекс сети. «Домашние» продукты (соль, масло, специи) в отдельной сумме и не входят в итог.
5. **Замена блюда:** пересчёт одной ячейки с той же корзиной, отклонённые варианты запоминаются в плане и не предлагаются снова; батч-пара меняется целиком.

Каждое блюдо несёт короткое объяснение (`why`): что доедаем, укладывается ли в бюджет, готовим ли на два дня.

## Данные

`backend/internal/seed/data/`

## Админка

`/admin` открыта аккаунтам из `ADMIN_EMAILS` (через запятую); остальным ручки `/api/admin/*` отвечают 404. Вкладки: **обзор** — счётчики (аккаунты, входы за неделю, недели, свои рецепты, семьи, подписки на push, комментарии, ответы «как было?», покупки, ошибки), столбики по дням (посетители по `sid` аналитики, недели, регистрации) за 7–90 дней, события по имени с числом сессий, страны и магазины недель за 30 дней, рецепты по лайкам; **аккаунты** — последние 100 с датой регистрации, последним входом и числом недель; **ошибки** — ошибки браузера: фронт ловит `error` и `unhandledrejection` и шлёт событие `js_error` (сообщение, стек, адрес, браузер) в ту же аналитику; **логи** — последние 1000 записей zap из кольцевого буфера в памяти (`logger.Ring`, уровень info+), с фильтром по уровню; после рестарта буфер пустой, полный лог — у контейнера.

## Роли, рецепты базы из админки, модерация

Роли — `users.role`: пусто, `moderator`, `admin`; почты из `ADMIN_EMAILS` всегда админы. Права (`service/admin.go`): admin — всё; moderator — обзор, рецепты базы, модерация, ошибки браузера. Роли и логи сервера — только admin. Роль назначается во вкладке «Аккаунты»; свою менять нельзя. `/api/me` отдаёт `perms`, по ним приложение показывает вкладки.

Вкладки живут в адресе: `/admin/users`, `/admin/moderation`, `/admin/recipes/olivier` (форма правки), в кабинете — `/me?tab=family`; «назад» и обновление возвращают туда же.

**Рецепты базы** правятся во вкладке «Рецепты»: поиск по названию, id или тегу, форма (название, фото, подводка, приём, время, «на два дня», техника, теги, продукты из базы, шаги), новый рецепт получает id из названия латиницей. Запись идёт в `recipes` / `recipe_ingredients` с `edited_at`, и сидинг такие строки больше не трогает; удаление мягкое (`deleted`), старые планы не ломаются. После сохранения сервер перечитывает каталог из БД и подменяет его целиком (`planner.CatalogRef`, ценники общие) — правка видна сразу, без рестарта.

**Модерация своих рецептов.** Рецепт всегда виден автору и по его ссылке (так работают семейные недели). Кнопка «поделиться» отправляет его на публикацию: статус `checking` — нейросеть (gpt-5-nano) проверяет, что это настоящее блюдо без рекламы, ссылок, брани и опасных советов; `approved` — рецепт на сайте (автор, раздел «От пользователей» внизу каталога, sitemap); `review` — нейросеть усомнилась или недоступна: очередь модератора, человек смотрит в течение суток, старше 20 часов подсвечивается; `rejected` — с причиной для автора. Автор видит статус под рецептом в кабинете: «Проверяем…», «Не прошёл автопроверку — проверим вручную в течение 24 часов, пока виден только вам», «Опубликован», «Отклонён: …». Ручки: `POST /api/me/recipes/{id}/publish`, `GET /api/admin/moderation`, `POST /api/admin/moderation/{id}` `{approve, note}`.

**Подробность рецептов.** Стандарт подробного рецепта записан в `ai.DetailStandard` (подготовка первым шагом, у каждого шага огонь, минуты и признак готовности, подача, 6–12 шагов). Он общий для трёх мест: кнопка «Расписать подробнее» в форме рецепта в админке (тот же `POST /api/me/recipes/ai`), автопроверка при публикации (если блюдо настоящее, но расписано скупо, нейросеть присылает подробную версию: статус `improve`, автор видит её под рецептом и либо «Принять и опубликовать», либо «Оставить как есть» — тогда ручная проверка) и массовая доработка базы: `go run ./cmd/racionai detail -to ru` пишет `internal/seed/data/recipes_detail.json` (id → подводка и шаги; название не меняется), seed накладывает его поверх коротких шагов для рецептов, которых не правили из админки. После доработки переводы шагов (en/de и остальные) нужно пересобрать. Пока у OpenAI нет кредитов, команда не запускалась.

**Комментарии** принимают подмножество Markdown (жирный, курсив, зачёркнутый, код, списки, цитаты, ссылки — `internal/markdown`, HTML экранируется до разметки, ссылки только http(s) с nofollow); на странице рецепта — панель кнопок над полем и фото иконкой. Страницы ошибок 404/403/500 рендерятся одним шаблоном `error.html`, паника в обработчике ловится (`withRecover`), при недоступном бэкенде nginx отдаёт статическую `50x.html` в том же оформлении; `/ru/…` постоянно перенаправляется на адрес без префикса.

## Архитектура бэкенда

Слои сверху вниз, зависимости только вниз:

```
transport/http   ── разобрать запрос → вызвать сервис → отдать JSON или HTML. Ничего не знает про SQL.
service          ── сценарии (Accounts, Plans, Recipes, Catalog, Events): правила, валидация, планировщик.
                    На входе ctx и простые аргументы, на выходе доменные значения и ошибки из domain.
                    Хранилище — интерфейсы-порты (UserRepo, PlanRepo…), объявленные здесь же.
storage/postgres ── репозитории на pgx: только SQL и маппинг строк; ошибки pgx → domain.ErrNotFound/ErrConflict.
domain           ── сущности (User, Session, PlanRecord, Purchase, Extra…) и ошибки (ErrNotFound, ValidationError{Key}).
planner, i18n, geo, localprices, rosstat, seed, db — как были: предметная область и инфраструктура.
```

`cmd/server/main.go` — единственное место сборки: конфиг → логгер → БД → каталог → фоновые синхронизации →
`postgres.New(pool)` → `service.New(repos, catalog)` → `transport.New(deps)`. Второй транспорт (Kafka-консьюмер,
пакетное задание, gRPC) — ещё один пакет под `internal/transport/`, который получает те же `service.Services`;
сервисы и хранилище не меняются. `ValidationError.Key` — ключ i18n, текст подбирает транспорт по языку запроса.
Сервисы тестируются без БД и без HTTP (`internal/service/service_test.go`, хранилище в памяти).

Логи — [zap](https://github.com/uber-go/zap): JSON по умолчанию, `LOG_FORMAT=console` для разработки, `LOG_LEVEL=debug|info|warn|error`.
У фоновых задач именованные логгеры (`geo`, `rosstat`, `localprices`, `http`), каждый запрос пишется одной строкой с методом, путём, статусом и временем.

## Безопасность и нагрузка

Что стоит между пользователем и данными:

- **Сессии** — случайный токен 32 байта в cookie `HttpOnly; SameSite=Lax; Secure` (за https), 90 дней, просроченные чистятся раз в сутки. Пароли — bcrypt. Cross-site JSON-запросы не проходят: CORS не включён, Lax-cookie на чужой POST не уходит.
- **Лимиты** — nginx: вход и регистрация 10/мин с адреса, API 20 запросов/с; бэкенд (`transport/http/ratelimit.go`, token bucket в памяти): вход ещё и 20 попыток на почту за 10 минут, сборка недели и замены 60/мин, аналитика 60 пачек/мин, записи 120/мин, всё API 600/мин. Ответ 429 с `Retry-After`.
- **Адрес клиента** — nginx перезаписывает `X-Forwarded-For` своим значением, подсунуть чужой IP (лимиты, страна) нельзя. За Cloudflare замените на `CF-Connecting-IP`.
- **Заголовки** — CSP без inline-скриптов (тема и скрипт SSR вынесены в `/theme.js` и `/ssr.js`), `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`; ответы `/api` — `Cache-Control: no-store`. HSTS включается на TLS-терминаторе.
- **Доступ к плану** — ссылка на план общая: смотреть, отмечать купленное и добавлять товары может любой, у кого она есть (список на другом телефоне). Менять блюда, переименовывать и удалять — только владелец; гостевой план (без аккаунта) правит любой, кто знает ссылку. Свои рецепты правит и удаляет только автор.
- **Ввод** — все тела ограничены (4–64 КБ, nginx 256 КБ), поля обрезаются по длине, id планов проверяются на uuid до запроса в БД, невалидный uuid → 404, а не 500. HTML собирается `html/template`, номера продуктов в шагах — с ручным экранированием; JSON-LD экранирует `<`.
- **БД** — пул 16 соединений, `statement_timeout` 15 с, соединения обновляются раз в час; порт Postgres опубликован только на `127.0.0.1`. Индексы под все запросы кабинета (`plans_user`, `purchases_user_date`, `user_recipes_user`, PK по `plan_checks`). События старше 180 дней удаляются.
- **HTTP-сервер** — таймауты чтения 15 с, записи 30 с, простоя 120 с, заголовки до 64 КБ; graceful shutdown 10 с.
- **Логи** — путь, метод, статус, время; без query-строк, тел и почты.

Что осталось на совести оператора: сменить `POSTGRES_PASSWORD`, поставить TLS и HSTS, задать `BASE_URL`, настроить бэкапы Postgres (`pg_dump` по крону) и мониторинг `/healthz`. Лимиты в памяти — на один инстанс; при нескольких инстансах их надо переносить в nginx/Redis. На тысячу активных пользователей запас большой: сборка недели ~10 мс, каталог в памяти, один Postgres.
