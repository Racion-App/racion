Конфиг хостового nginx сервера (`/etc/nginx/sites-enabled/racion`), копия для истории. Деплой его не накатывает:
менять на сервере вручную, проверять `nginx -t`, потом `systemctl reload nginx`. Резервные копии держать вне
`sites-enabled`: nginx подключает там всё подряд, и копия даёт «duplicate upstream».

На сервере с двумя портами Docker Compose блок `upstream racion_app` подключает
`/etc/nginx/snippets/racion-active-frontend.conf`. При первой установке узнайте порт работающего
фронтенда через `docker compose port frontend 80` и запишите в файл одну строку, например
`server 127.0.0.1:8091;`. Проверьте `nginx -t` и перечитайте конфигурацию.
При следующих выкладках `deploy.sh` сам переключает этот файл после проверки нового контейнера.
Второй порт указывается как `backup` на случай отказа основного.
Запускающему скрипт пользователю нужны права на запись файла, проверку и reload хостового nginx.

Кеш страниц (04.11.2026): `/recipes` и `/recipe/<id>` на любом языке, без сессии, 2 часа, ключ — адрес со строкой
запроса и cookie страны. Нужен против ботов, перебирающих сочетания фильтров каталога (тысячи запросов в минуту).
Чтобы сбросить кеш: `sudo rm -rf /var/cache/nginx/racion/* && sudo systemctl reload nginx`.
